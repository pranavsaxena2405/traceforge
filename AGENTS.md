# AGENTS.md - TRACEFORGE Engineering Guidelines

## Project Purpose
TRACEFORGE is an open-source developer platform building behavioral CI/CD and runtime intelligence for AI applications. It captures, stores, analyzes, and evaluates traces generated by AI agents, LLM chains, retrieval pipelines, and tools.

## Current Milestone
**TRACEFORGE FOUNDATION v0.1**: Smallest complete vertical slice powering local trace ingestion, storage, and retrieval.
Flow: `Example Application -> SDK -> OpenTelemetry Instrumentation -> Collector -> PostgreSQL -> REST API`

## Prohibited Technologies for Milestone v0.1
Do **NOT** introduce or add code for any of the following in this milestone:
- Kafka / Event Streaming Queues
- Redis / Caching
- ClickHouse / OLAP engine
- Kubernetes / Helm
- Terraform / Cloud IaC
- OAuth / JWT / Authentication frameworks
- Frontend UI / React / Next.js
- LangChain / LangGraph integrations
- Model Context Protocol (MCP) integrations
- Third-party LLM provider SDKs (OpenAI, Anthropic, etc.)
- Cloud service dependencies (AWS, GCP, Azure)

## Architecture Rules
1. **Separation of Concerns**: SDK, Collector, Storage, API, and Example components must remain strictly decoupled.
2. **Storage Location**: Database models (`models.py`) and connections (`db.py`) reside under `collector/app/`.
3. **OpenTelemetry Primitives**: SDK builds upon standard OpenTelemetry Python primitives (`TracerProvider`, `Tracer`, `Span`, `SpanExporter`). Do not invent custom tracing primitives when OTel standards apply.
4. **Ingestion Contract**: Milestone v0.1 uses an OTel-aligned custom JSON REST ingestion contract (`POST /api/v1/traces`), not a full OTLP gRPC receiver.
5. **Idempotence**: Trace ingestion must safely handle duplicate trace/span IDs via PostgreSQL upsert/idempotent update.

## Coding Standards
- **Python**: Python 3.12+ with standard type hints (`str`, `dict[str, Any]`, `list[Span]`, `Optional`, etc.).
- **Models**: Pydantic v2 for API schemas, SQLAlchemy 2.0 mapped models for persistence.
- **Error Handling**: Graceful failure in the SDK to prevent telemetry network errors from crashing host application logic.
- **Logging**: Structured logging using standard library `logging`.

## Testing Requirements
- Comprehensive `pytest` test suite covering SDK, API endpoints, error conditions, and database persistence.
- Tests must verify safe ingestion idempotence and complete parent-child span context hierarchy.

## Security Rules
- Configured exclusively via environment variables (`DATABASE_URL`, `TRACEFORGE_COLLECTOR_URL`, etc.).
- No hard-coded secrets, tokens, or local credentials in source code.
